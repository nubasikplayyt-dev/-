# Портфель по критериям — Telegram Mini App

Мини-приложение показывает сводки, которые агент мониторинга пишет в отдельный
GitHub-репозиторий с данными. Приложение этот репозиторий **только читает** и
ничего в него не пишет.

Состав:

| Папка | Что внутри |
|---|---|
| `src/` | Фронтенд: Vite + React + TypeScript, `@telegram-apps/sdk-react` |
| `src/data/` | Весь разбор данных репозитория: схемы zod и парсеры |
| `src/mock/` | Копия раскладки репозитория данных для разработки и тестов |
| `worker/` | Cloudflare Worker: бот (`/start`, `/mute`, `/unmute`) и прокси приватного репозитория |
| `deploy/` | Файлы, которые ставятся **в репозиторий данных**: workflow уведомлений и скрипт отправки |

## Откуда берутся данные

Приложение читает из репозитория данных:

```
config/watchlist.json        разделы по странам и список бумаг
CRITERIA.md                  расшифровки критериев C1–C8 и P1–P3
data/<id бумаги>/status.json вердикт, критерии, поле watch
data/<id бумаги>/events.jsonl лента событий, по одному JSON в строке
feed/feed.json               общая лента для блока «Важное»
```

Публичный репозиторий читается напрямую с `raw.githubusercontent.com`,
приватный — через Cloudflare Worker (см. ниже). Ответы кэшируются на 5 минут,
кнопка «Обновить» на главном экране сбрасывает кэш.

Битая строка в `events.jsonl` не роняет экран: она пропускается с записью
в консоль, остальные события читаются как обычно. То же с бумагой, у которой
не хватает обязательных полей, — пропадает только она, а не весь раздел.

## Локальный запуск

```bash
npm install
cp .env.example .env     # и вписать свой репозиторий данных
npm run dev              # http://localhost:5173
```

Чтобы поднять интерфейс без доступа к репозиторию данных, поставьте в `.env`
`VITE_USE_MOCK=1` — приложение возьмёт данные из `src/mock/`.

Вне Telegram приложение открывается как обычная страница: SDK видит, что
клиента нет, и тихо переходит в браузерный режим. Deep link эмулируется
параметром адресной строки: `http://localhost:5173/?startapp=sber`.

Другие команды:

```bash
npm test          # тесты парсинга events.jsonl и watchlist.json
npm run build     # сборка в dist/ (проверяет и типы)
npm run preview   # посмотреть собранное
```

## Добавить бумагу

Код менять не нужно — всё в репозитории данных.

1. В `config/watchlist.json` добавьте запись в `assets[]` нужного раздела:

   ```json
   {
     "id": "moex",
     "ticker": "MOEX",
     "name": "Московская биржа",
     "short_name": "Мосбиржа",
     "isin": "RU000A0JR4A1",
     "logo": "assets/logos/moex.png"
   }
   ```

   Обязательны только `id`, `ticker` и `name`. Если `id` не указать, он
   возьмётся из тикера.

2. Создайте папку `data/moex/` с файлами `status.json` и `events.jsonl`.
   Без них бумага всё равно появится на главном экране — с пометкой
   «Нет оценки» и пустой лентой.

3. Логотип класть необязательно. Если файла по пути из `logo` нет (или поле
   не указано), приложение рисует круг с первыми двумя буквами тикера;
   цвет считается по хэшу тикера, поэтому у одной бумаги он всегда один и тот же.

Приложение подхватит бумагу при следующем обновлении — пересобирать и
передеплоивать ничего не нужно.

## Добавить страну

Тоже только данные. Новый объект в `sections[]` файла `config/watchlist.json`:

```json
{
  "id": "us",
  "title": "Акции США",
  "country": "US",
  "currency": "USD",
  "yield_floor_pct": 3,
  "assets": []
}
```

`country` — код ISO-3166 alpha-2. Флаг рисуется по коду, список стран в коде
не зашит: любой корректный двухбуквенный код даст свой флаг, неизвестный —
нейтральный значок 🌐. Дальше добавляйте бумаги в `assets[]` этого раздела,
как описано выше.

## Деплой фронтенда на GitHub Pages

Workflow лежит в `.github/workflows/miniapp-pages.yml` этого репозитория
и срабатывает на изменения в `miniapp/`.

1. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
2. Там же, в **Settings → Secrets and variables → Actions → Variables**,
   задайте переменные (это не секреты, они попадают в собранный бандл):

   | Переменная | Значение |
   |---|---|
   | `DATA_OWNER` | владелец репозитория данных |
   | `DATA_REPO` | имя репозитория данных |
   | `DATA_BRANCH` | ветка, обычно `main` |
   | `DATA_PROXY` | адрес Cloudflare Worker — **только** для приватного репозитория данных |

3. Пуш в `main` соберёт и опубликует сайт. Адрес будет вида
   `https://<владелец>.github.io/<репозиторий>/`.

GitHub Pages бесплатны только для публичных репозиториев. Репозиторий
**данных** при этом может оставаться приватным — его читает воркер.

## Cloudflare Worker: бот и прокси

Воркер нужен в двух случаях: репозиторий данных приватный и/или нужны
команды `/mute` и `/unmute`. Если репозиторий публичный и команды не нужны,
воркер можно не разворачивать.

```bash
cd worker
npm install
npx wrangler login
npx wrangler kv namespace create STATE     # id из вывода вписать в wrangler.toml
```

Поправьте `[vars]` в `wrangler.toml`: `DATA_OWNER`, `DATA_REPO`, `DATA_BRANCH`
и `ALLOWED_ORIGIN` (адрес сайта на GitHub Pages, с него разрешены запросы).

Секреты задаются отдельно и в репозиторий не попадают:

```bash
npx wrangler secret put GITHUB_TOKEN             # fine-grained, только Contents: Read на репозиторий данных
npx wrangler secret put TELEGRAM_BOT_TOKEN       # токен бота из @BotFather
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET  # любая длинная случайная строка
npx wrangler deploy
```

Прокси отдаёт только те пути, которые нужны приложению (`config/watchlist.json`,
`CRITERIA.md`, `data/*/status.json`, `data/*/events.jsonl`, `feed/feed.json`,
`schema/`, `digests/*.md`, `assets/logos/*`) — остальное он не пропустит.

Адрес воркера впишите в переменную `DATA_PROXY` репозитория (шаг 2 деплоя)
и в `.env` для локальной разработки.

### Подключить вебхук бота

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://<воркер>.workers.dev/tg/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>"}'
```

Команды бота:

| Команда | Что делает |
|---|---|
| `/start` | Запоминает `chat_id` и показывает его — его нужно положить в секрет репозитория данных |
| `/mute <id бумаги>` | Не присылать уведомления по этой бумаге |
| `/unmute <id бумаги>` | Вернуть уведомления |
| `/muted` | Показать список заглушённых |

Список заглушённых бумаг хранится в KV воркера.

## Регистрация Mini App в @BotFather

1. `/newbot` — создать бота, забрать токен.
2. `/newapp` — выбрать бота, указать название, описание, картинку 640×360
   и **URL сайта** с GitHub Pages.
3. Задать короткое имя приложения (например `portfolio`). Ссылка на
   приложение получится вида `https://t.me/<бот>/portfolio`.
4. `/setmenubutton` — повесить приложение на кнопку меню бота (необязательно).

Deep link вида `https://t.me/<бот>/portfolio?startapp=sber` открывает сразу
экран нужной бумаги. Такую ссылку приложение кладёт в кнопку «Открыть» в
уведомлениях.

## Уведомления: что поставить в репозиторий данных

Скопируйте туда два файла из `deploy/`:

```
deploy/notify.yml       →  .github/workflows/notify.yml
deploy/scripts/notify.py →  .github/scripts/notify.py
```

Workflow срабатывает на push в `main`, затрагивающий `data/*/events.jsonl`,
находит добавленные этим пушем строки и шлёт в Telegram те, где `notify: true`.
Остальные строки и битый JSON он пропускает.

Секреты репозитория **данных** (Settings → Secrets and variables → Actions):

| Секрет | Обязателен | Значение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота из @BotFather |
| `TELEGRAM_CHAT_ID` | да | Ваш `chat_id`, его показывает бот по `/start` |
| `MINIAPP_LINK` | нет | `https://t.me/<бот>/<короткое имя>` — без него не будет кнопки «Открыть» |
| `MUTES_URL` | нет | `https://<воркер>.workers.dev/mutes` — без него `/mute` не учитывается |
| `MUTES_SECRET` | нет | То же значение, что `TELEGRAM_WEBHOOK_SECRET` воркера |

Токен бота и `chat_id` нигде в коде не хранятся — только в секретах.

Предохранители: за один запуск уходит не больше 15 сообщений, а при ручном
запуске или force-push, когда диапазон пуша неизвестен, скрипт сравнивает
с предыдущим коммитом, а не со всей историей.

## Замечания

- Пакеты `@telegram-apps/*` помечены в npm как устаревшие в пользу `@tma.js/*`.
  Здесь используется `@telegram-apps/sdk-react` — он рабочий, но при обновлении
  стоит иметь в виду переезд.
- `telegram-web-app.js` со страницы не подключается специально: SDK сам
  общается с клиентом Telegram, а два моста в одной странице конфликтуют.
- Аналитики, трекеров и сторонних шрифтов в приложении нет.
