# Портфель по критериям — приложение для Android

Приложение показывает сводки, которые агент мониторинга пишет в репозиторий
данных [`nubasikplayyt-dev/invest-watch`](https://github.com/nubasikplayyt-dev/invest-watch),
и само сообщает о новых событиях. Репозиторий оно **только читает** и ничего
в него не пишет.

Ни сервера, ни бота, ни Telegram для работы не нужно: приложение ходит прямо
в GitHub, а уведомления показывает сам телефон.

| Папка | Что внутри |
|---|---|
| `core/` | Чистая Kotlin-логика без Android: разбор `watchlist.json`, `status.json`, `events.jsonl`, `feed.json` и `CRITERIA.md`, подписи метрик, выбор событий для уведомлений. Тесты: `core/src/test` |
| `app/` | Android-приложение: Compose, OkHttp, DataStore, WorkManager, уведомления |

## Как поставить на телефон

APK собирает GitHub Actions — ничего устанавливать на компьютер не нужно.

1. Откройте **Actions → Portfolio APK** в репозитории и выберите последний
   удачный запуск (зелёная галочка).
2. Внизу страницы, в разделе **Artifacts**, скачайте `portfolio-apk`.
   Это zip-архив — распакуйте, внутри `portfel-po-kriteriyam.apk`.
3. Перекиньте APK на телефон и откройте его. Android спросит разрешение
   «Установка неизвестных приложений» для того приложения, из которого вы
   открываете файл (обычно это «Файлы» или браузер) — разрешите.
4. При первом запуске разрешите уведомления.

APK подписан отладочным ключом. Этого хватает для установки на свой телефон;
для публикации в Google Play понадобился бы свой ключ.

Обновление: скачайте APK нового запуска и установите поверх — данные и
настройки сохранятся, пока ключ подписи не меняется.

## Что умеет

**Главный экран.** Лента «Важное» — последние события с важностью `critical`
и `high` из `feed/feed.json`. Ниже разделы по странам из `watchlist.json`:
заголовок с флагом и карточки бумаг с вердиктом. Точка рядом с тикером
означает непрочитанные события с `notify: true`.

**Экран бумаги.** Шапка с логотипом, названием, тикером и ISIN, вердикт и дата
обновления, пометки «Сырьевая» и «Только для квалифицированных», ссылки на
IR-страницу и раскрытие, если они указаны. Дальше таблица критериев C1–C8 и
P1–P3 со значком статуса и пометкой — нажатие раскрывает расшифровку из
`CRITERIA.md`. Блок «Что отслеживаем» — поле `watch`. Лента событий, новые
сверху, с фильтром по типу и отдельной вкладкой «Дивиденды». У каждого события
видно, какие критерии оно затронуло и каким стал вердикт.

**Уведомления.** Раз в несколько часов приложение смотрит репозиторий и
показывает уведомление о каждом новом событии с `notify: true`: значок
важности, бумага, заголовок и сводка. Нажатие открывает экран этой бумаги.
Переключатель на экране бумаги выключает уведомления по ней одной — это
замена командам `/mute` в боте.

Постоянных служб, будильников и фоновых сервисов приложение не держит:
проверка идёт через `WorkManager`, только при наличии сети. Точное время
выбирает система, при экономии батареи проверка может задержаться.

## Откуда берутся данные

```
config/watchlist.json          разделы по странам и список бумаг
CRITERIA.md                    расшифровки критериев C1–C8 и P1–P3
data/<id>/status.json          вердикт, критерии и список watch
data/<id>/events.jsonl         лента событий, по одному JSON в строке
feed/feed.json                 общая лента (поле items) для блока «Важное»
```

Читается напрямую с `raw.githubusercontent.com`. Ответы кэшируются OkHttp,
кнопка «Обновить» в шапке читает заново. Репозиторий, владельца и ветку можно
поменять в настройках приложения — по умолчанию это `nubasikplayyt-dev/invest-watch`,
ветка `main`. Приватный репозиторий приложение читать не умеет.

Форматы, на которые приложение рассчитано:

- `status.json` — вердикт и дата во вложенном объекте `status`, `watch` —
  массив строк, `criteria` — объект с кодами. Набор критериев может быть
  неполным: у ЗПИФ заполнены только C1, C2, C3, C6, P1 и P3.
- `events.jsonl` — по схеме `schema/event.schema.json`. У события есть
  собственные `criteria` и `verdict`.
- `importance` — только `critical`, `high` и `medium`; в «Важное» попадают
  первые два, уведомления приходят по полю `notify`.
- `CRITERIA.md` — критерии лежат таблицами (`| C1 | Вечная тема | … |`).
  Разметка заголовками тоже понимается.

Битая строка в `events.jsonl` пропускается, остальные читаются как обычно.
Бумага без обязательных полей пропадает одна, а не весь раздел. Разбор собран
в `core/src/main/kotlin/app/portfolio/core/Parse.kt`; тест сверяет перечисления
приложения с настоящим `schema/event.schema.json`, так что расхождение с
репозиторием данных упадёт в тестах, а не в интерфейсе.

Файлы `digests/*.md` приложение не показывает — это сводки запусков агента.

## Добавить бумагу

Код менять не нужно — всё в репозитории данных.

1. Добавьте запись в `assets[]` нужного раздела `config/watchlist.json`:

   ```json
   {
     "id": "MOEX",
     "ticker": "MOEX",
     "name": "Московская биржа",
     "type": "stock",
     "isin": "RU000A0JR4A1",
     "is_commodity": false,
     "logo": "logos/MOEX.svg",
     "ir_url": null,
     "disclosure_url": null
   }
   ```

   Обязательны только `id`, `ticker` и `name`. Остальное приложение покажет,
   если оно есть: `is_commodity` и `commodity` дают пометку «Сырьевая»,
   `qualified_only` — «Только для квалифицированных», `ir_url` и
   `disclosure_url` — ссылки в шапке.

   Если в `ticker` лежит ISIN (так у ЗПИФ), крупно показывается `id` —
   `PARUS-SBL`, а не `RU000A104172`.

2. Создайте папку `data/MOEX/` с файлами `status.json` и `events.jsonl`.
   Без них бумага всё равно появится — с пометкой «Нет оценки» и пустой лентой.

3. Логотип класть необязательно. Если файла по пути из `logo` нет (папка
   `logos/` в репозитории пока пустая), приложение рисует круг с первыми двумя
   буквами тикера; цвет считается по хэшу, поэтому у бумаги он всегда один.

Приложение подхватит бумагу при следующем обновлении — переустанавливать
ничего не нужно.

## Добавить страну

Новый объект в `sections[]` файла `config/watchlist.json`:

```json
{
  "id": "us",
  "title": "Акции США",
  "country": "US",
  "currency": "USD",
  "yield_floor_pct": 1.0,
  "assets": []
}
```

`country` — код ISO-3166 alpha-2. Флаг рисуется по коду, список стран в коде
не зашит: любой корректный двухбуквенный код даёт свой флаг, неизвестный —
значок 🌐. Дальше добавляйте бумаги в `assets[]`, как описано выше.

## Разработка

```bash
# Тесты ядра — Android SDK не нужен
./gradlew -PcoreOnly=true :core:test

# Полная сборка — нужен Android SDK
./gradlew :core:test :app:lintDebug :app:assembleDebug
```

Логику, которую можно проверить без Android, кладите в `core/` и покрывайте
тестами: `app/` остаётся тонким слоем поверх неё.

В `core/src/test/resources/invest-watch/` лежит срез репозитория данных.
`watchlist.json`, `status.json`, `CRITERIA.md` и схема скопированы как есть;
в `events.jsonl` и `feed.json` добавлены примеры событий — в репозитории они
пока пустые, а без событий нечего проверять. Примеры помечены строкой-комментарием.

## Что стало с версией для Telegram

В папке `miniapp/` лежит ранее сделанный Telegram Mini App с тем же набором
экранов, бот для уведомлений и GitHub Action к нему. Для Android-приложения
ничего из этого не нужно — оно работает само по себе. Удалять не обязательно:
если захотите читать портфель ещё и с компьютера через Telegram, эта версия
готова к работе.
